03
Data Cleaning runs in parallel Server
🧹
cleanGoogleAdsData()
server/src/services/cleaners/googleAdsCleaner.js
Normalises Google Ads CSV column names, casts numeric fields, and stamps every row with a fixed sub_platform.
IN: raw CSV rows[] OUT: UnifiedRow[]
Output row shape
platform: "Google" sub_platform: "Google Ads" campaign: string spend: number revenue: number clicks: number impressions: number conversions: number
🧹
cleanMetaAdsData()
server/src/services/cleaners/metaAdsCleaner.js
Normalises Meta Ads CSV fields and maps publisher_platform to the appropriate sub-platform label.
IN: raw CSV rows[] OUT: UnifiedRow[]
sub_platform mapping
"facebook" → "Facebook" "instagram" → "Instagram" "audience…" → "Audience Network" (other) → "Meta"
Two UnifiedRow[] arrays merged into one
↓
04
Merge & Schema Mapping Server
🔗
mergeDatasets()
server/src/services/merge/mergeEngine.js

IN: ...UnifiedRow[][] OUT: UnifiedRow[] (merged)
→
🗺️
unifiedSchemaMapper
server/src/services/schema/unifiedSchemaMapper.js

05
Analytics Engines runs in parallel Server
📊
generateAnalytics()
server/src/services/analytics/analyticsEngine.js
Primary engine. Computes totals, blended rates, per-platform breakdown, and per-campaign breakdown in one pass.
IN: UnifiedRow[] OUT: full KPI object
Output keys
totalSpend, totalRevenue totalClicks, totalImpressions totalConversions overallCTR, overallROAS conversionRate googleRevenue, metaRevenue platformBreakdown: { [name]: {...} } campaignBreakdown: CampaignMetric[]
📉
calculateKPIs()
server/src/services/analytics/kpiEngine.js
Legacy KPI aggregator. Returns simple totals only. Superseded by analyticsEngine.js.
IN: UnifiedRow[] ⚠ Deprecated
Output keys
total_spend, total_revenue total_clicks, total_impressions total_conversions // no breakdown data
🏷️
generateCampaignBreakdown()
server/src/services/analytics/campaignEngine.js
Groups rows by campaign name, computes per-campaign ROAS/CTR/CPC, and assigns a performance status tag.
IN: UnifiedRow[] OUT: CampaignMetric[]
Status thresholds
top ROAS ≥ 4.0 moderate ROAS ≥ 2.0 underperforming ROAS ≥ 1.0 waste ROAS < 1.0
KPI object + merged dataset → AI service
↓

Interactive Filtering NEW Client-side · No API call
🔽
Campaign Dropdown
client/app/page.js — selectedCampaign state
Options built from [...new Set(campaignBreakdown.map(c => c.name))]. Selecting a campaign filters to that campaign's rows only.
IN: unique campaign names OUT: selectedCampaign string
+
🔽
Platform Dropdown
client/app/page.js — selectedPlatform state
Options limited to platforms present in kpis.platformBreakdown. Both filters compose with AND logic.
IN: platformBreakdown keys OUT: selectedPlatform string
↓   IIFE recomputes on every render   ↓
⚡
filteredKpis (IIFE)
client/app/page.js — inline derivation after const kpis = ...
Filters kpis.campaignBreakdown by the two active dropdowns, then reduces the matching rows to recompute all totals and rebuild platformBreakdown from scratch. No useMemo needed — campaignBreakdown is ≤~10 entries.
IN: campaignBreakdown[], selectedCampaign, selectedPlatform OUT: filteredKpis (same shape as kpis)
↓   filteredKpis propagated to all dashboard sections   ↓
📊
8 KPI Cards
All values read from filteredKpis.*
🏷️
Platform KPI Cards
Re-rendered from filteredKpis.platformBreakdown
📈
Revenue / Pie / Funnel
revenueSpendData, pieData, funnelData derived from filteredKpis
📝
Exec Summary
ROAS, conversion rate, best platform from filteredKpis
Not filter-responsive (by design): Scatter, radar, and area charts use hardcoded sample data — there is no per-row historical data in the API response to derive them dynamically. AIInsights text is also static per upload — re-calling the AI per filter change would be expensive and serve no purpose.
